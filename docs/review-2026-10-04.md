# Release readiness review — 2026-10-04

Reviewed tracked extension at `142276d`. The untracked settings study is not part of the extension. No implementation changes were made during this review.

Assessment: suitable for continued internal testing; close to a small tester alpha after the timing fix and fresh installed-browser verification. Not yet ready for a public store release. The unfinished design system is not the main blocker.

## Findings

### P1 — Scrolling queue has no age deadline

`src/ui/floating-comments.ts:89–94, 124–135` bounds pending entries by count (60), not age. A row must have clearance before another comment is launched. A burst followed by a quiet period leaves old messages in the collector snapshot, so queued messages can continue entering long after the associated moment. There is no enqueue timestamp or playback-time age check. Timed comments eventually leave the eight-second active window, but live chat can persist much longer.

The agreed five-second playback-time deadline is not implemented. Add enqueue time, expire pending entries before admission, freeze age during pause, account for playback speed, and clear on seeks/navigation. Test long comments in Quiet mode, bursts followed by silence, pause/resume and 2× playback. Quiet/Balanced/Lively still map to 1/3/6 rows (`src/ui/display-settings.ts:110`); available-height Lively is also only a proposal.

Evidence: source inspection; no new live-site reproduction in this review.

### P2 — Open tabs can overwrite newer preferences

`src/browser/app.ts:25` reads preferences once. `src/browser/preferences.ts:10–11` replaces the complete stored preference object. No storage-change subscription exists.

Example: open tabs A and B; A changes auto-load from Off to 100; B, still holding Off, changes its text size. B saves its entire stale object and silently restores Off. A change in one tab also does not update already-open tabs. A single per-tab save queue does not serialize multiple tabs.

Subscribe to external changes and persist changed fields through a merge/serialization strategy that handles concurrent writers. Test two actual extension tabs, including unrelated simultaneous edits. Separate global preferences from per-tab presentation state if that is the intended UX.

Evidence: source inspection; not runtime-reproduced in this review.

### P2 — Off still performs collection and hidden rendering

`src/browser/app.ts:123–155` keeps both collectors and the playback observer running while visibility is false. `src/ui/panel.ts:392–433` still serializes message snapshots and rebuilds the entire chat list when content changes. This also runs in floating modes where the chat-box list is hidden. Off suppresses preloading and translation scheduling, but does not suspend the ordinary collection/render path.

A busy live chat therefore keeps doing DOM work even after the user turns Sideline off. Avoid constructing hidden message rows, pause unnecessary collection when disabled, and rescan on activation. Measure busy-chat CPU and DOM churn in box, floating and Off states before optimizing further. No measured CPU regression is claimed here.

### P2 — Release verification is not green

GitHub run 35846310045 for the reviewed commit reports 197 passed, 1 failed, 1 flaky, 2 skipped. The repeated WebKit failure is `tests/browser/translation.spec.ts:138`: an animation expected to retain currentTime 2000 instead reports 0 after translation. Chromium's newest-message scroll-following test passed on retry. Determine whether the WebKit failure is an implementation issue or a test/ResizeObserver timing race; do not silently dismiss it.

`.github/workflows/check.yml:21–27` places the installed Firefox smoke after the all-engine suite, so it was skipped on this run. Separate browser-engine jobs and installed-extension smoke jobs so a Safari-later failure cannot suppress Chrome/Firefox evidence. WebKit failure alone need not block a Chrome-only alpha, but the supported-browser checks must be independently green.

Run: https://github.com/RobinPourtaud/sideline/actions/runs/35846310045

### P2 — Collection documentation contradicts implementation

`docs/collection.md:7` prohibits automatic pagination, and `README.md:27` says automatic loading is absent. The actual extension invokes YouTube's continuation handler and automatically loads the saved 100/300/500 target. README also advertises a removed pause button and describes settings as floating-mode-only. PRIVACY.md more accurately describes the current behavior.

Update the decision record and user documentation before open-source/store release. Reassess collection on the basis of the actual automatic loader; the older passive-DOM-only rationale is insufficient. YouTube policy approval has not been established by this review.

## Remediation pass

The subsequent implementation adds playback-time queue expiry, available-row Lively, per-field preference storage with legacy reads and cross-tab updates, collection suspension while Off, and no hidden chat-list rendering in floating modes. Failed local writes retain their page-local values. CI now runs engine checks and installed Chrome/Firefox checks independently. Initial ResizeObserver notifications no longer reset floating animations, motion edits explicitly preserve currentTime, and scroll-following accounts for feed geometry changes.

Collection and README documentation now describe the actual optional loader and current controls. Experimental design files are outside the extension lint boundary. SECURITY.md records the upstream node-forge advisory's development-only ADB path; no unverified crypto patch or downgrade was introduced. The Android minimum-version metadata is retained for manifest validation; release support remains desktop-only and Android must not be selected as a supported store platform.

The original findings above describe the checkpoint reviewed, not an assertion that they remain present after these changes. Final validation is recorded in docs/testing.md.
